POST /api/entries/:id/progress  [sahibi]   *** GUNLUK OKUMA ***
   Istek : { "current_page": 214 (>=1), "confirm"?: true, "date"?: "2026-10-23" (varsayilan bugun; gelecek olamaz;
             start_date'ten once olamaz -> 400) }
   KURALLAR (kesin):
     1. delta = current_page - entry.current_page (kayitli son sayfaya gore).
     2. delta > 0 : [v2 - ATLANAN GUNLER] Son log gununden (hic log yoksa start_date'ten)
        'date' gunune kadar atlanan gun varsa (n>=2 gun, en fazla son 90 gun), delta o n gune
        ESIT BOLUNUR (artan kismi son gunlere) ve o log satirlari estimated=true olur:
        tahmini gunler ORTALAMAYA girer, REKOR ve SERI'ye GIRMEZ. Atlanan gun yoksa
        (n=1: ardisik ya da ayni gun) delta o gunun satirina eklenir, gercek (estimated=false)
        kalir; ayni gun birden cok guncelleme TEK satirda toplanir. Ornek: 20 Eki basladi,
        23 Eki'de '150. sayfa' -> 20,21,22,23 Eki'ne 37/37/38/38 sayfa (hepsi tahmini).
        PATCH ile status='bitti' yapildiginda kalan sayfalar da tahmini sayilir (800 sayfalik
        kitabi 'bitti' isaretlemek rekor kirmaz).
     3. delta < 0 : [v4] DUZELTME icin confirm:true ZORUNLU; yoksa 400 code="CONFIRM_REQUIRED" (arayuz
        "214'ten 2'ye dusuyor, emin misin?" sorar). current_page<1 hep 400 (0/bos/gecersiz kabul edilmez).
        Onayli geri alma gecmis log'lari SILMEZ: duzeltme gununun satirina negatif fark yazilir (net toplam
        current_page ile tutarli kalir; yanlis yazip sonra duzeltmek sonucu bozmaz).
     4. delta = 0 : islem yok, 200 doner (log eklenmez).
     5. current_page > total_pages -> 400. current_page < 0 -> 400.
     6. current_page == total_pages -> status 'bitti', end_date = date (varsayilan bugun).
     6b. [v4] Ilk guncelleme (hic log yok) ve start_date yoksa (planlandi -> ilk ilerleme) onceki okuma bilinmez:
        tahmini yazilir (rekora girmez).
     7. status 'planlandi' ise ilk ilerlemede 'devam' olur, start_date = date.
        'bitti'/'birakildi' kayda ilerleme girilirse 'devam'a doner (end_date silinir).
   Cevap : 200 { "entry": entry,
                 "delta": 14,                  // bu cagridaki fark (negatif olabilir)
                 "pages_read_on_date": 31,     // o gunun bu kitap icin toplami
                 "date":"2026-10-23",
                 "finished": false,
                 "spread_days": 1,           // [v2] delta kac gune bolundu (1 = bolunmedi)
                 "estimated": false }       // [v2] bolundu/tahmini ise true -> arayuz 'X gune dagittik' diyebilir

GUNLUK ORTALAMA FORMULU
  Gun-bazli model kullanilir (her kitap icin):
   - Gercek log varsa o gunlerin sayfasi aynen kullanilir ("real").
   - Kitabin okunan toplam sayfasi (bitmisse total_pages, devam ise current_page)
     log toplamindan fazlaysa (kullanici guncelleme yapmamis), FARK, kitabin
     araligindaki (start_date..end_date, devam ise ..bugun) logsuz gunlere
     esit bolunur ("estimated"). Hic logsuz gun yoksa son gune eklenir.
   - Kitap bazinda  avg_pages_per_day = okunan_sayfa / (end_date|bugun - start_date + 1)
        avg_source = "logs" (hic oranlama gerekmedi) | "estimated" (en az biraz oranlandi)
        Hic log yoksa bitmis kitap: total_pages / (end-start+1) ; devam eden:
        current_page / gecen gun (bugun dahil).
   - Kullanici bazinda avg = (tum kitaplarin gun-bazli sayfa toplami) /
        (kitap araliklarinin BIRLESIMINDEKI benzersiz gun sayisi). Ayni gunde iki
        kitap okunduysa o gun bir kez sayilir; arada hic kitabi olmayan gunler
        sayilmaz. period filtresi araliklari ve gunleri o doneme kirpar.
   - REKOR ve SERI sadece GERCEK (estimated=false) log gunlerinden hesaplanir (tahmini gunler
        rekor/seri olamaz).
   - [v2] Liderlik "average" tablosuna girmek icin en az 3 gunluk veri araligi gerekir (1 gunluk
        kitapla tablonun basina cikilmasin). /users/:id/stats avg_pages_per_day bu esigi uygulamaz.

GET /api/entries/:id/open-days   [sahibi]   -> { "days":[ {"date":"2026-10-21","state":"open"|"estimated","pages":0} ], "count":3 }
   Soru sorulacak gunler: baslangic tarihinden (en fazla son 90 gun) bugune kadar, hic kaydi OLMAYAN ("open") ve
   tahmini ("estimated": kullanici atlayip toplu sayfa girince dagitilmis) gunler. Gercek girilmis ve "okumadim"
   (0) isaretli gunler listelenmez.
PUT /api/entries/:id/day-logs    [sahibi]
   Istek : { "days":[ {"date":"2026-10-21","pages":30}, {"date":"2026-10-22","pages":0} ], "add"?:true }
           ya da { "skip_open":true }   // acik ("open") gunlerin hepsi "okumadim" (0) olur
   - pages = O GUN okunan sayfa (kumulatif sayfa NO degil). 0 = okumadim (gun kapanir, bir daha sorulmaz).
   - add:true -> o gunun mevcut GERCEK degerine ekler (arayuzde "bugun +N ekle"); yoksa degeri degistirir.
   - Satir gercek (estimated=false) olur: seriyi (streak) ve rekoru gunceller.
   - current_page otomatik guncellenir (current_page = onceki + fark). Tahmini bir gunu degistirirken fark diger
     tahmini gunlere dagitilir, "su an X. sayfadayim" degismez; dagitilacak tahmini gun kalmadiysa current_page degisir.
   - Toplam sayfayi asarsa 400; son sayfaya ulasilirsa kitap "bitti" olur; gelecek tarih / baslangictan onceki tarih 400.
   Cevap : 200 { "entry":entry, "applied":2, "open_days":[...kalan acik gunler...] }
   Mevcut POST /progress (kumulatif sayfa + opsiyonel date) AYNEN calisir; geriye donuk tarih icin de kullanilabilir.

[v7] KAYIT ACARKEN GECMIS GUNLERI DOLDURMA  (POST /api/entries)
   Kitap 'devam', current_page>0 ve start_date gecmisteyse arayuz KAYIT ACARKEN su secimi sormali ve gondermeli:
     "backfill":"manual" + "days":[{"date":"2026-10-20","pages":20}, ...]   // GUN GUN DOLDUR
         days = start_date..DUN arasi gunler icin o gun okunan sayfa. Bos birakilan/verilmeyen gun = 0 (okumadim,

         (arayuz "bugun: kalan N" gostersin). Toplam > current_page -> 400.
     "backfill":"spread"                                                  // GUNLERE ESIT DAGIT
